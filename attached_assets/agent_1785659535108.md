InstaVault — Agent Build Guide
This document is written for the AI agent that will implement InstaVault.
Read this alongside architecture.md and implementation-plan.md.

Quick Context
What we're building: An Android APK (Expo/React Native) that downloads Instagram media (posts, reels, stories, carousels, highlights) by accepting a URL from the user.
Backend: Express 5 API (already scaffolded in this monorepo at artifacts/api-server/) — extend it, don't replace it.
Media extraction engine: yt-dlp — a Python CLI tool that handles Instagram's internal API. The backend wraps it via execa.

STEP 1 — OpenAPI Spec
Write the full OpenAPI spec at lib/api-spec/openapi.yaml.

Critical schema decisions:

MediaInfo.type must be an enum: post | reel | story | highlight | carousel | profile_pic | igtv
MediaFormat.formatId is passed verbatim to yt-dlp's --format flag
CarouselItem must include its own formats array (each item has independent quality options)
Error responses must use { "error": { "code": string, "message": string } } shape
After writing the spec, run:

pnpm --filter @workspace/api-spec run codegen

Do NOT read the generated files — they are large. Just verify codegen exits 0.

STEP 2 — Backend Routes
Extend artifacts/api-server/src/routes/index.ts to mount:

Create these new files:

Key implementation notes for ytdlp.ts:

The raw yt-dlp --dump-json output is large and complex. You only need these fields:

id, title, description, uploader, uploader_id, thumbnail, upload_date,
webpage_url, ext, width, height, duration, formats[]

From formats[], filter and map to your MediaFormat[]:

Include only formats with vcodec != "none" OR pure audio formats
For video: prefer formats with both video + audio merged (look for acodec != "none" && vcodec != "none")
Synthesize a "best" option (yt-dlp format string: "bestvideo+bestaudio/best")
For carousel/playlist: _type == "playlist" with entries[]
Error mapping from yt-dlp stderr:

const PRIVATE_PATTERNS = [/private/, /login required/i, /not accessible/i];
const NOT_FOUND_PATTERNS = [/404/, /does not exist/, /deleted/i];
const RATE_LIMIT_PATTERNS = [/429/, /rate.?limit/i, /too many requests/i];

Critical Rules for This Project
DO
✅ Validate ALL input URLs against Instagram domain allowlist before passing to yt-dlp
✅ Use execa (not exec/spawn) to call yt-dlp — it handles escaping and timeouts
✅ Clean up temp files in finally blocks and on response close events
✅ Cache resolve results for 5 minutes (same URL = same yt-dlp call)
✅ Use expo-file-system.downloadAsync() for the actual file download on mobile (not fetch)
✅ Save to gallery via expo-media-library.createAssetAsync() — not raw file system copy
✅ Request permissions before accessing media library / notifications
✅ Handle the carousel case: yt-dlp returns _type: "playlist" with entries[]
✅ Use FlashList (not FlatList) for history list
✅ All SQLite operations: use parameterized queries (never string interpolate)
DON'T
❌ Never accept Instagram credentials from users
❌ Never shell-interpolate the URL into a command string — always use positional args
❌ Never leave temp files on disk after response ends
❌ Never hardcode the API base URL — use EXPO_PUBLIC_API_URL
❌ Never use console.log on the backend — use req.log or the logger singleton
❌ Never call yt-dlp without a --socket-timeout and process timeout in execa
❌ Never fetch the CDN URL directly from the client — always proxy through your backend
❌ Never store full download history on the server — it's client-only (privacy)
Common Pitfalls & Solutions
yt-dlp "login required" on public content
Instagram occasionally rate-limits aggressively. Solutions:

Add --sleep-interval 2 --max-sleep-interval 5 to yt-dlp args
Rotate user agent: --user-agent "Mozilla/5.0 ..."
Return a 429 with Retry-After: 30 to the mobile client
Client shows countdown and auto-retries
Large carousels (10+ items)
Don't download all items in one yt-dlp call — use --playlist-items <n> to fetch one at a time
Queue each item as a separate download entry in Zustand
Video + Audio merge (yt-dlp behavior)
For Instagram, most high-quality formats already have merged audio. But if you see vcodec without audio, use yt-dlp format string: "bestvideo[height<=1080]+bestaudio/best[height<=1080]" — yt-dlp will merge them using ffmpeg. Ensure ffmpeg is available in the server environment.

expo-media-library on Android 13+
Android 13+ uses granular permissions (READ_MEDIA_VIDEO, READ_MEDIA_IMAGES) instead of READ_EXTERNAL_STORAGE. Expo SDK 52 handles this automatically — just call requestPermissionsAsync() and it requests the right ones.

Share intent on Android: URL in intent extras
When Instagram shares a URL via the Share sheet, it comes in Intent.EXTRA_TEXT. In Expo, access it via:

import * as Linking from 'expo-linking';
const url = await Linking.getInitialURL();
// OR listen to Linking events for app-already-open case

Scoped storage and temp files on Android 10+
Use FileSystem.cacheDirectory for temporary download files
After download, move to permanent location via FileSystem.moveAsync()
Then use MediaLibrary.createAssetAsync(permanentPath) to save to gallery
The temp file in cacheDirectory is auto-cleaned by the OS under storage pressure
