Task

Build the InstaVault Android app — a fast, focused Instagram media downloader.

**Product identity:** The tool power users keep in their dock — feels like it was built by someone who actually uses it daily. Direct, zero-friction, no-nonsense. Like a Swiss Army knife designed by a minimalist: every feature earns its space.

**Vibe:** Dense, fast, and precise — like a cockpit where every control is exactly where you expect it. Dark-first, but beautiful in both modes. The interface should feel like it's been tuned for speed. Make a bold, deliberate color choice derived from the product's identity — not gray/white emptiness. Calm means restful color, not absence of color.

**Pages (expo-router file-based routing):**
- `app/(tabs)/index.tsx` — Home: URL paste input + Fetch button + active downloads list + last 5 history items. The URL input is the hero element.
- `app/(tabs)/history.tsx` — Full download history with filter chips (All/Videos/Photos/Audio) + search
- `app/(tabs)/settings.tsx` — Quality prefs, concurrent downloads (1/2/3), theme, about section
- `app/download/[id].tsx` — Individual download detail: progress bar, file info, cancel/retry actions
- `app/onboarding.tsx` — First-launch 3-card walkthrough (3 cards: paste link / choose quality / saved to gallery). Skip if MMKV flag set.

**Tab bar:** 3 tabs — Home (download icon), History (clock/history icon), Settings (gear icon). Support NativeTabs (iOS 26 liquid glass) + ClassicTabs fallback. The existing `(tabs)/_layout.tsx` already has the NativeTabs/ClassicTabs split — extend it to 3 tabs.

**Available API hooks (import from `@workspace/api-client-react`):**
```
useHealthCheck() — GET /api/healthz
useResolveMedia(options) — POST /api/resolve, accepts { url: string }. This is a MUTATION (useMutation). Use it as: const resolveMedia = useResolveMedia(); resolveMedia.mutate({ url })
useDownloadMedia(params?, options?) — GET /api/download?url=...&formatId=...&index=...
getDownloadMediaQueryKey(params?) — returns the query key for the download hook
```

**Set base URL in app/_layout.tsx** (at the top level, outside any component):
```typescript
import { setBaseUrl } from '@workspace/api-client-react';
setBaseUrl(`https://${process.env.EXPO_PUBLIC_DOMAIN}`);
```

**Key behaviors to implement:**
1. URL input on Home calls `useResolveMedia` mutation → on success shows a bottom sheet with thumbnail, author, caption, quality selector
2. "Download" button in the sheet builds the download URL: `/api/download?url=...&formatId=...&index=...` and uses `expo-file-system` `downloadAsync()` to fetch it
3. Download queue in Zustand (`store/downloadQueue.ts`) — drives progress UI and notifications
4. After download completes: save to gallery via `expo-media-library.createAssetAsync()`, insert into SQLite history
5. History list: `expo-sqlite` for persistence, use FlashList from `@shopify/flash-list`
6. Settings: use `react-native-mmkv` for persistent settings storage
7. Check MMKV flag `hasSeenOnboarding` in root layout; redirect to onboarding on first launch
8. Share intent: handle `expo-linking` `getInitialURL()` in root layout to pre-fill URL input

**Critical rules:**
- Do not use emojis anywhere in the UI
- Use ALL the provided API hooks
- Use @expo/vector-icons (Feather or MaterialCommunityIcons) for all icons — no text-only buttons
- Use FlashList (not FlatList) for history list
- All SQLite operations: use parameterized queries (never string interpolation)
- Never hardcode the API base URL — use the setBaseUrl approach above
- UUID generation: use `Date.now().toString() + Math.random().toString(36).substr(2, 9)`
- Handle expo-media-library and expo-notifications with Platform.OS checks (web doesn't support them)
- Micro-interactions: animated progress bar fill (Reanimated), completion checkmark, download state transitions
- Supporting screens (onboarding) deserve the same polish as the main app
- Prioritize information clarity — utility app, not a social feed. Make it feel fast and precise.
